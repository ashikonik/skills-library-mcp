# Script and Story Editing

Take a script that exists and make it work: shorter, sharper, better-structured, and built for the format it will be performed in.

This skill is about **editing material that already exists**. Writing a script from nothing is a different job; so is writing an article or blog post. What unites the work here is that the output has to survive contact with a runtime — a narration, an edit, a speaker, a viewer with a short attention span.

## The Core Job

Change the draft so that it says one thing, in the fewest words that carry it, in a shape that fits the time it has.

Three questions, in order:

1. **What is this piece trying to do?** Name it in one sentence before touching anything. If the draft does not obviously do one thing, that is the first edit.
2. **What is the spine?** The claim, the turn, the reveal — the thing that must survive every cut. Protect it.
3. **What is only supporting it?** Everything else. This is what gets cut.

Do not summarize the changes. Deliver the edited script.

## Working Rules

**Length is a constraint, not a target.** When the user names a runtime — 60 seconds, 90 seconds, 3 minutes — treat it as a hard budget. Read aloud at a natural pace and count. Underrunning is as wrong as overrunning; if the piece is thin at the target length, say so rather than padding.

**Cut on meaning, not on syllables.** A sentence that carries no information goes. A sentence that carries information badly stays until it is rewritten. Trimming words from a sentence that still says the thing is the last resort, not the first move.

**The hook is a promise.** The first line has to make the viewer want the rest. If the piece opens on context the viewer does not yet care about, move the payoff forward or cut the setup entirely. Offer three hooks when the piece needs one — different angles, not cosmetic variations.

**Structure before sentences.** Fix the order of the beats before polishing any individual line. A well-written sentence in the wrong place is still in the wrong place.

**Keep the voice.** The author's fingerprints — their word choices, their rhythm, their odd turns of phrase — are what makes the piece work. Editing is not the opportunity to write it in your own voice. If a line is fine, leave it alone; the goal is a tighter draft, not a different draft.

**Say what you cut.** When a cut changes the meaning, or when you removed a section the user clearly cared about, note it in a line after the script. A silent deletion of something deliberate is a bug.

## Shapes That Fit Common Formats

| Format | Shape |
|---|---|
| Short-form vertical (30–60 s) | Hook → one idea → payoff. No setup section. |
| YouTube essay (8–12 min) | Cold open with the payoff → thesis → three beats → close. |
| Voiceover / narration | Written to be *heard*. No parentheticals, no bullet lists, no "as shown in the video". |
| Product demo script | Problem in one line → what it does → proof → what to do next. |
| Documentary / brand film | Scene beats with timecodes; each beat states its own visual. |
| Talking-head interview | Question → answer → the sentence worth pulling as a quote. |

When the user has not named a format, infer the most likely one from the material and the context, and say which one you assumed.

## Common Failure Modes

- **Opening with throat-clearing.** "In today's fast-paced world…" The piece starts before it says anything. Cut to the first real sentence.
- **One idea smuggled in three.** A script that is really about two things is two scripts. Split it or pick one.
- **Padding for length.** Repetition of a point already made, restating the premise at the end, or a summary that adds nothing. Cut.
- **Cutting the spine.** Removing the beat the piece depends on because it was long. If the beat has to go, the piece has to change — say so rather than leaving a hole.
- **Titles that describe instead of promise.** "How We Built X" describes; "We Almost Didn't Ship X" promises. Offer the second kind.
